# Автотесты портфолио на Java

Самостоятельный Maven-проект для проверки этого сайта в реальном браузере. Использует Selenide поверх Selenium WebDriver, JUnit Jupiter и Page Object. Существующий набор [Playwright](../playwright/README.md) продолжает запускаться отдельно.

## Выбор решений

Решения и версии сверены с официальной документацией **21.10.2026**. Для небольшого React-сайта основной критерий — стоимость поддержки сценариев и разбор падений.

| Решение | Что даёт этому проекту |
| --- | --- |
| Selenium WebDriver | Управление настоящим браузером; на чистом Selenium ожидания и диагностику нужно организовать самостоятельно. |
| **Selenide поверх Selenium** | Проверки `shouldBe` / `shouldHave` ожидают состояние элемента. Меньше повторяющегося кода для динамического интерфейса. |
| **JUnit Jupiter** | Параметризованные проверки, assertions и расширение для жизненного цикла браузера. Дополнительные возможности TestNG здесь не требуются. |
| **Maven Wrapper** | Одинаковая зафиксированная версия Maven локально и в CI; отдельно устанавливать Maven не нужно. |
| **Page Object** | Локаторы и операции страницы собраны в одном месте; тесты описывают ожидаемое поведение. |

| Компонент | Версия |
| --- | --- |
| Java | Компиляция для Java 21; CI — Temurin 25 LTS |
| Selenide | 7.19.0 |
| Selenium | 4.51.0, транзитивная зависимость Selenide |
| JUnit Jupiter / BOM | 6.1.3 |
| Maven / Wrapper | 3.10.0 / 3.3.4 |
| Maven Compiler / Surefire | 3.16.0 / 3.6.0 |

Основание выбора: [Selenide: ожидания и проверки](https://selenide.org/documentation.html), [релиз Selenide 7.19.0 и версия Selenium](https://selenide.org/2026/10/10/selenide-7.19.0/), [JUnit и поддержка Java](https://docs.junit.org/6.1.3/overview.html), [JUnit в Maven](https://docs.junit.org/6.1.3/running-tests/build-support.html), [Maven](https://maven.apache.org/download.cgi), [Maven Wrapper](https://maven.apache.org/tools/wrapper/), [Java LTS](https://www.oracle.com/java/technologies/java-se-support-roadmap.html).

## Запуск

Нужны **JDK 21+**, `java` в `PATH` (или корректный `JAVA_HOME`), Node.js из корневого `.nvmrc` и Google Chrome. В CI используется Temurin 25. Первый запуск скачивает Maven, Java-зависимости и подходящий драйвер браузера, поэтому нужен доступ к сети. Драйвер подбирает встроенный [Selenium Manager](https://www.selenium.dev/documentation/selenium_manager/).

В первом терминале из корня репозитория:

```sh
npm ci
npm run dev -- --port 4177 --strictPort
```

Во втором терминале, PowerShell:

```powershell
cd selenim
.\mvnw.cmd test
```

В Linux / macOS:

```sh
cd selenim
sh ./mvnw test
```

Сайт должен быть доступен на `http://127.0.0.1:4177/`. Порт 4177 должен быть свободен; существующий запуск Playwright тоже может его занимать. Maven не запускает веб-сервер самостоятельно. Для проверки production-сборки вместо `npm run dev` выполните `npm run build`, затем `npm run preview -- --port 4177 --strictPort`.

При запуске через **Run Test** в VS Code сервер тоже нужно предварительно запустить и оставить работающим. Настройки в [`.vscode/settings.json`](../.vscode/settings.json) задают UTF-8 для JVM тестов и её вывода, чтобы русские `@DisplayName` отображались корректно. Настройки Surefire из `pom.xml` применяются к запуску через Maven, а не к кнопке **Run Test**.

Открыть видимое окно Chrome:

```powershell
.\mvnw.cmd test "-Dselenide.headless=false"
```

Проверить опубликованный сайт, без локального веб-сервера:

```powershell
.\mvnw.cmd test "-Dselenide.baseUrl=https://masloymax.github.io/portfolio/"
```

Этот запуск проверяет опубликованную версию: изменения из рабочей папки появятся там после деплоя. Для Linux / macOS замените `.\mvnw.cmd` на `sh ./mvnw`.

Запустить один класс:

```powershell
.\mvnw.cmd test "-Dtest=PortfolioTest"
```

Настройки передаются через `-D`:

| Свойство | По умолчанию |
| --- | --- |
| `selenide.baseUrl` | `http://127.0.0.1:4177/` |
| `selenide.browser` | `chrome` |
| `selenide.headless` | `true` |
| `selenide.browserSize` | `1440x1000` |
| `selenide.timeout` | `6000`, миллисекунды ожидания условия |

## Устройство и покрытие

Файлы находятся в `src/test/java/ru/masloy/portfolio/`:

- `BrowserExtension.java` создаёт отдельные `SelenideDriver` и конфигурацию для каждого теста, сохраняет диагностику падения и закрывает браузер.
- `PortfolioPage.java` содержит локаторы, действия и доступ к элементам страницы.
- `PortfolioTest.java` проверяет профиль, образование, языки, навыки, навигацию, аккордеон опыта, клавиатурное управление, темы и контакты.
- `ResponsiveTest.java` проверяет мобильные размеры 320 и 390 пикселей через эмуляцию Chromium.

Одинаковое поведение для нескольких компаний, тем или размеров экрана проверяется параметризованными тестами. Clipboard API подменяется для проверки успешного копирования адреса, ошибки и восстановления; системный буфер обмена пользователя не изменяется. Внешние контакты проверяются по адресам и атрибутам ссылок.

Каждый сценарий получает новый браузер и собственное хранилище. Индивидуальный `SelenideDriver` позволяет не менять общие статические настройки Selenide. Набор выполняется последовательно: для такого объёма это проще и экономнее по памяти. Мобильная эмуляция требует Chromium; при выборе другого браузера пропускаются только зависящие от неё тесты.

Проверки ожидают конкретное состояние интерфейса. Фиксированных `Thread.sleep` и автоматических повторов упавших тестов нет. Ожидаемые данные заданы в тестах независимо от `src/profile.ts`, поэтому ошибочное изменение сайта не изменяет одновременно и ожидание. При намеренном обновлении портфолио соответствующие ожидания нужно пересмотреть.

## Отчёты и CI

- `target/surefire-reports/` — результаты JUnit в TXT/XML.
- `target/selenide/` — PNG и HTML страницы при падении, когда браузер уже доступен.
- `target/preview.log` — журнал Vite preview в CI.

Папка `target/` исключена из Git. При ошибке сначала проверьте сообщение в отчёте, затем снимок и HTML. Если браузер не смог запуститься, смотрите ошибку запуска в выводе Maven.

- `ERR_CONNECTION_REFUSED` в снимке или HTML означает, что браузер не смог подключиться к сайту. Для адреса по умолчанию запустите из корня `npm run dev -- --port 4177 --strictPort` и дождитесь готовности сервера.
- `ReportEntry ... failure artifacts = '.../имя'` — общий префикс файлов `имя.png` и `имя.html`, а не текст исключения. В VS Code откройте подробности упавшего теста, чтобы увидеть исключение и стек вызовов.
- `SLF4J(W): No SLF4J providers were found` — [предупреждение об отсутствии реализации логгера](https://www.slf4j.org/codes.html#noProviders). В `pom.xml` подключён `slf4j-simple` в области `test`; если IDE продолжает показывать предупреждение, обновите Maven-проект, чтобы новая зависимость попала в classpath тестов.

[Workflow Java UI tests](../.github/workflows/selenim.yml) запускается на push в `main`, pull request и вручную. Он устанавливает зависимости, собирает текущую ревизию сайта, поднимает локальный preview, ожидает его готовности и выполняет тесты в headless Chrome. После прогона preview останавливается, отчёты и журнал сохраняются в артефакт `selenim-report` на 7 дней, включая неуспешный прогон.

Этот workflow проверяет сборку текущего коммита независимо от GitHub Pages. Публикацией сайта занимается существующий workflow деплоя.
